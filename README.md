# 문서 변환 및 메일머지 자동화 프로그램

Electron + Node.js + JavaScript로 만든 데스크톱 프로그램입니다. 파이썬은 사용하지 않습니다.

- **탭 1. 문서 양식 변환기**: 엑셀/CSV(`.xlsx`, `.xls`, `.csv`) 파일 또는 한글(`.hwpx`, `.hwp`) 문서 속 표의 컬럼을 다른 엑셀 양식에 매핑하여 변환. 매핑 규칙은 이름 붙여 프리셋으로 저장해 다음에 바로 불러오거나 수정할 수 있습니다. 내부적으로 Extract(읽기) → Transform(매핑) → Load(서식 적용 저장)의 ETL 구조로 동작하며, 결과 파일은 헤더 색상/테두리와 자동 맞춤 열 너비, 숫자 열 천단위 서식이 적용된 상태로 생성됩니다.
  - 컬럼 자동 매핑: 완전히 같은 이름 → **동의어 사전**(의미는 같지만 표기가 다른 경우, 예: "성명"↔"이름") → 편집거리 기반 유사 매칭(오타·공백 차이) → **한글 자모 단위 유사 매칭**(음절이 통째로 달라 보여도 자모 하나만 다른 한글 오타, 예: "성명"↔"승명") 순서로 자동 연결을 시도합니다. 단계마다 **타겟 컬럼 전체를 먼저 본 뒤** 정하므로 타겟 컬럼 순서와 상관없이 결과가 같습니다(예: 타겟 [성명, 이름] ← 원본 [이름]이면 같은 이름끼리 먼저 연결되고, "성명"이 동의어로 "이름"을 가져가지 않습니다). 동의어 사전은 AI 모델 없이 결정적으로 동작하며 📖 버튼으로 직접 추가/수정할 수 있습니다. 어느 단계든 후보가 모호하면(같은 이름의 원본이 둘, 두 타겟이 같은 원본을 같은 정도로 원함 등) 자동 매핑하지 않고, 작업대에 후보와 **이유**를 함께 보여줍니다.
  - **① 파일 인식**: 파일을 고르면 무엇을 어떻게 읽었는지 바로 보여주고 고칠 수 있습니다.
    - 헤더 행 자동 감지: 맨 위 10행 중 "절반 이상 채워지고 대부분이 이름 같은 글자"인 첫 행을 헤더로 봅니다. 1행에 "2026년 명단"류 제목이 있거나, 머리글 칸 하나가 비어 데이터 행이 더 많이 채워져 있어도 헤더를 찾고, 두 줄 머리글은 아래 줄을 씁니다. 틀리면 **헤더 행** 목록(각 행의 앞부분 미리보기)에서 직접 고를 수 있습니다.
    - 머리글이 빈 열에 값이 있으면 버리지 않고 "(이름 없음) C열"로 넣고 알려줍니다. 가로로 병합된 머리글은 뒤 칸이 이름을 이어 받습니다("주소", "주소_1").
    - 헤더 위에서 뺀 행, 완전히 빈 행 수, CSV 글자 인코딩(자동 판별 결과, 직접 바꾸기 가능, 깨진 글자 수), 확장자와 실제 내용이 다른 파일(예: 이름만 .xlsx인 CSV, .xls로 내려받은 HTML 표 — 내용에 맞춰 읽음), 1904 날짜 체계(맥용 엑셀) 파일을 알려줍니다.
  - **매핑 작업대**: ②단계의 **시각화** 스위치를 켜면(기본은 꺼짐, 마지막 선택을 기억) 연결 상태와 저장될 결과를 함께 보며 고칠 수 있습니다. 끄면 기존처럼 매핑 표만 보이고, 변환 확인 창에서 저장될 표의 앞부분을 보여줍니다. 모든 조작은 실행 취소(Ctrl+Z)·다시 실행(Ctrl+Y)으로 되돌릴 수 있고, 원본 파일은 바뀌지 않습니다.
    - **요약 바**: 연결 수, 확인 필요(이름만 비슷해서 연결한 것), 연결 없음, 필수 빈칸 행, 중복 행, 직접 고친 값 수를 칩으로 보여줍니다. 칩을 누르면 해당 항목으로 이동하거나 문제 있는 행만 보여줍니다.
    - **연결 보기**: 한 줄에 [원본 컬럼]—선—[타겟 컬럼]을 나란히 보여주고, 선 색·배지로 연결 이유(같은 이름·동의어·비슷한 이름·직접 연결·프리셋·규칙)를 구분합니다. 연결 안 된 원본 컬럼을 오른쪽 목록에서 끌어다 놓거나, 타겟 컬럼을 눌러 고르기 창에서 고릅니다(이름·초성·값으로 찾기, 이름이 비슷한 정도와 값 모양(전화번호·날짜 등)으로 추천). 비슷한 이름 연결은 [맞음]으로 확인합니다.
    - **컬럼이 많을 때**: 타겟이 12열을 넘으면 "확인 필요 → 연결 없음 → 직접 연결 → 자동 연결됨(접힘)" 순서로 묶어 보여줍니다. J/K로 다음·이전 확인 항목, Y로 맞음, C로 바꾸기, [남은 N개 모두 맞음]으로 한꺼번에 처리할 수 있습니다. 비슷한 저장된 프리셋이 있으면 띠로 알려줍니다(자동 적용은 하지 않음). 보이는 줄·열만 화면에 그려 수백 열도 가볍게 다룹니다.
    - **결과 미리보기**: 저장될 표 그대로(날짜·숫자 표시 형식 포함, 첫 칸은 원본 파일의 실제 행 번호) 50행씩 보여줍니다. 칸을 더블클릭하거나 Enter로 값을 직접 고칠 수 있고(Enter 확정 · Esc 취소 · Tab 다음 칸), 고친 칸은 노란색으로 표시되며 [원래 값으로] 되돌릴 수 있습니다. 숫자 열에 숫자로, 날짜 열에 "YYYY-MM-DD"로 고친 값은 그 종류로 저장됩니다. 열이 많으면 첫 열 고정, 열 지도, "문제 있는 열만"으로 원하는 열을 빨리 찾을 수 있습니다.
    - 기존 매핑 표는 **목록 보기**로 언제든 전환해 쓸 수 있고, 두 보기는 같은 연결 상태를 공유합니다.
  - **원본 합치기**: ①단계의 [+ 원본 추가]로 다른 파일(엑셀·CSV·한글 표)을 붙이면, 기준 컬럼(예: 사번)이 같은 행끼리 이어 원본(A)에 컬럼을 더합니다. 기준 컬럼은 값이 겹치는 정도·값이 겹치지 않는 정도·이름·코드 모양으로 자동 추천하며(이름이 달라도 값으로 찾음, 예: 사번 = 직원번호) 직접 바꿀 수 있습니다. "원본(A)에 있는 행만"(기본) 또는 "양쪽 행 모두"를 고를 수 있습니다. "양쪽 행 모두"는 짝이 없는 행·기준값이 빈 행·기준값이 겹치는 행까지 모두 덧붙여 **어느 쪽 행도 빠지지 않습니다**. 한 기준값에 행이 여럿이면 "첫 행만 잇기"(기본) 또는 "모두 잇기(행이 늘어남)"를 고릅니다. 빠지거나 덧붙인 행은 이유별로 **행 번호와 함께** 분석 결과·저장 확인 창에 알려줍니다.
    - 기준값은 **글자 그대로 비교**합니다(엑셀 숫자 123과 글자 "123"은 같음, "00123"과 "123"은 다름). 앞자리 0만 다른 코드를 같은 값으로 보려면 추가 원본마다 "앞자리 0 무시"를 켭니다. 켜기 전에 정확히 비교할 때와 무시할 때 연결되는 행 수, 그리고 무시하면 같아지는 서로 다른 값(예: 0123 · 123)을 먼저 보여줍니다.
  - **결과 시트 나누기**: ③단계의 "결과 시트"에서 타겟 컬럼 하나를 고르면 그 값마다 시트를 따로 만들어 저장합니다(예: 부서명 → 영업팀·개발팀 시트, 맨 앞에 전체 시트 함께 넣기 선택 가능). 값 종류가 적고 대부분 채워진 컬럼, 이름이 부서·지점·구분 같은 컬럼을 추천합니다. 빈 칸 묶음은 "(빈 값)" 시트가 되며, 실제로 "(빈 값)"이라고 적힌 칸과는 따로 나뉩니다. 이 설정은 프리셋·매핑 규칙 파일에도 저장됩니다.
  - 저장 전 검증: B 컬럼을 "필수"로 지정하면 해당 값이 빈 행을, 그리고 모든 값이 완전히 같은 중복 행을 미리보기와 요약에 바로 표시합니다. 저장할 때는 요약(행 수 흐름·필수 빈칸·중복·확인 안 한 연결·고친 값 수)을 확인한 뒤 진행하거나 취소할 수 있습니다. 직접 고친 값은 그 파일 하나에만 해당하므로 프리셋·매핑 규칙 파일에는 저장되지 않습니다.
  - **④ 변환 파일 확인**: 저장한 파일을 **다시 열어** 시트 이름·순서, 헤더, 시트별 행 수, 모든 칸의 값(글자는 글자로 — 00123이 숫자로 바뀌지 않았는지, 숫자·날짜는 값과 표시 형식까지)을 저장하려던 표와 비교하고, ③단계에 결과·저장 경로·[폴더에서 보기]·행 수 흐름(원본 → 읽을 때 뺀 행 → 합치기 → 결과)·다른 칸 목록을 보여줍니다. 같은 폴더의 임시 파일에 쓰고 확인한 뒤 원래 이름으로 바꾸므로, 다시 열 수 없는 파일이면 기존 같은 이름의 파일을 덮어쓰지 않습니다. 큰 결과는 진행 막대와 [취소]가 있고, 확인은 별도 프로세스에서 해 창이 멈추지 않습니다.
- **탭 2. 서식 자동 기입**: 환자 인적사항을 한 번 넣고 제출 기관과 서류를 고르면, 등록해 둔 한글 서식에 내용을 채워 **한글로 바로 인쇄**합니다. 지금까지 엑셀(메일머지.xlsx)에 인적사항을 모아 두고 한글 메일머지로 서식마다 채우던 일을 대신합니다.

  - **인적사항은 저장하지 않습니다.** 화면(메모리)에만 있고, 출력이 끝나면 지웁니다. 인쇄에 쓴 채운 임시 파일은 인쇄 직후 지우고, 프로그램이 갑자기 꺼져 남은 임시 파일은 다음 시작 때 지웁니다. 진행 기록에도 값은 남기지 않습니다.
  - AI를 쓰지 않습니다. 모두 정해진 규칙으로 동작하고, 인적사항을 밖으로 보내지 않습니다.

  #### ① 서류 출력 (매일 쓰는 화면)

  1. **인적사항**: 이름 · 주민등록번호 · 주소 · 연락처 · 작성일(비우면 오늘). 고른 서류에 진료기간·주질병·질병분류기호·진단일 칸이 있으면 그 칸만 더 나타납니다.
     - 생년월일(6자리), 주민등록번호 한 자리씩({{1}}~{{13}}), 작성일 월·일 두 자리씩({{월1}}{{월2}}·{{일1}}{{일2}}), 진료기간("26.01.02~")은 넣은 값에서 자동으로 만듭니다. 서식에 "2026년 {{월1}}…"처럼 연도가 미리 찍혀 있으면 작성 연도로 맞춥니다.
  2. **제출 기관**: 주소의 시·군·구로 맞는 기관(양주시 → 양주시청, 서울 주소 → 서울형 포함)을 추천해 골라 둡니다. 직접 바꿀 수 있습니다.
  3. **신청 구분**: 세대주 / 세대원.
  4. **출력할 서류**: 그 기관의 서식이 지원 종류(긴급복지 국가형 · 경기도형 · 서울형 · 광주형 · 암환자 의료비)별로 나오고, 서식마다 들어 있는 서류 목차와 빈칸을 보여 줍니다.
  5. **서식 출력**: 부수를 정해 기본 프린터(설정에서 바꿀 수 있음)로 인쇄합니다. 한글이 없는 PC에서는 [한글 파일로 저장]으로 채운 .hwpx를 저장할 수 있습니다(저장한 파일에는 인적사항이 들어 있으니 다 쓴 뒤 지워 주세요).

  #### ② 서식 관리

  - 한글 서식(.hwp · .hwpx)이나 서식이 든 **폴더를 통째로** 끌어다 놓거나 [폴더째 추가]로 등록합니다. 파일·폴더 이름("양주시청-긴급복지지원 신청서(세대주).hwp", "★…", "보건소 암지원 신청서/…")으로 제출 기관 · 지원 종류 · 세대주/세대원 · 자주 쓰는 서식(★)을 알아보고, 확인 창에서 고친 뒤 등록합니다.
  - 서식 안의 **한글 메일머지 필드**({{이름}} · {{주민등록번호}} · {{1}}~{{13}} · {{월1}} … {{담당자 번호}})를 한글 없이 직접 읽어 필드와 서류 목차([서식 1호] 현장확인서 …)를 보여 줍니다. 지금까지 쓰던 필드 이름 29개는 모두 사전에 있어 그대로 채워지고, 사전에 없는 필드는 [검토]에서 고정 글자 · 출력할 때 입력 · 비워 둠 중에서 정합니다.
  - 메일머지 필드가 없는 서식은 서식 엔진의 자동 인식(머리글 옆 빈 칸, "라벨:  " 빈자리, 서명 줄, 날짜 틀 등)으로 채웁니다. [시험 저장]으로 가짜 예시 값을 채운 파일을 만들어 확인하세요.
  - .hwp 서식은 설치된 한글로 .hwpx로 바꿔 보관합니다(등록할 때, 또는 처음 출력할 때). 원본 파일은 바뀌지 않습니다.
  - 서식과 필드 연결은 이 PC에만 저장됩니다. [백업 내보내기]로 만든 .zip을 다른 PC에서 [백업 가져오기]하면 그대로 옮겨집니다.

  #### ③ 설정

  담당자 · 직위 · 담당자 번호(암환자 의료비 서식의 {{담당자}} 등), 기본 부수, 프린터 이름, [한글 연결 확인].

  #### 한글 연결 점검 (Windows)

  `tools\한글연결점검.bat`: 사용하실 PC에서 한글 자동 조작(변환·PDF·인쇄)이 되는지 확인합니다. 서식 파일(.hwp/.hwpx)을 bat 위로 끌어다 놓으면 그 서식을 .hwpx로 바꾸고, 메일머지 필드를 가짜 예시 값으로 채워 PDF로 만들어 `한글연결점검_결과` 폴더에 둡니다. `점검보고서.txt`에 한글 버전, 보안 모듈 등록 여부, 단계별 결과가 나옵니다.
  - 한글이 자동 조작으로 파일을 열 때 "접근 허용" 창이 뜰 수 있습니다. 한컴의 보안 모듈(FilePathCheckerModule)을 등록하면 이 창 없이 진행됩니다.

- **동의어 사전**: "성명"↔"이름"처럼 표기는 다르지만 같은 의미인 컬럼 이름을 자동 매핑 2단계에서 즉시 연결해 주는 기능입니다. 작은 임베딩/언어 모델 없이, 사용자가 직접 관리하는 텍스트 사전만으로 동작해 설치 용량·실행 속도·예측 가능성(틀린 추측으로 개인정보가 엉뚱한 칸에 들어가는 일이 없음)을 그대로 유지합니다. 자주 쓰는 동의어는 기본으로 포함되어 있고, 탭 1의 "📖 동의어 사전 관리" 버튼에서 한 줄에 한 그룹(쉼표로 구분)씩 직접 추가/수정할 수 있습니다.

## 설치 없이 바로 실행하기 (Windows)

1. 이 저장소 페이지에서 **Code → Download ZIP**으로 압축 파일을 내려받습니다.
2. 원하는 폴더에 압축을 풉니다.
3. 압축 푼 폴더 안의 **`run.bat`** 파일을 더블클릭합니다.
   - 최초 실행 시 필요한 패키지와 프로그램 실행 엔진(Electron, 약 100MB)을 자동으로 내려받습니다 (인터넷 연결 필요, 몇 분 정도 소요).
   - 이후 실행부터는 이미 설치된 패키지를 빠르게 확인만 하고 바로 프로그램이 열립니다 (보통 몇 초 이내). 업데이트로 새 패키지나 새 실행 엔진 버전이 필요해진 경우에도 자동으로 함께 설치됩니다.
   - 인터넷 연결이 없는 상태에서 실행하면, 이미 설치되어 있던 패키지 그대로 프로그램을 계속 엽니다.
   - 회사망처럼 외부 사이트가 제한된 곳에서는 최초 설치 때 `registry.npmjs.org`(패키지), `cdn.sheetjs.com`(엑셀 읽기 라이브러리), `github.com`과 GitHub 파일 서버(실행 엔진) 접속이 허용되어 있어야 합니다.

> **사전 준비**: PC에 [Node.js](https://nodejs.org/) **22.12 이상** (LTS 버전 권장)이 설치되어 있어야 합니다. `run.bat` 실행 시 Node.js가 없거나 버전이 낮으면 안내 메시지가 표시됩니다.
>
> **지원 운영체제**: Windows 10/11 64비트, macOS 13 이상, 64비트 Linux. (실행 엔진 Electron 44가 32비트 Windows와 macOS 12 이하를 지원하지 않습니다.)

## macOS / Linux에서 실행하기

`run.bat`은 Windows 전용입니다. macOS/Linux에서는 터미널에서 프로젝트 폴더로 이동한 뒤 아래 명령을 실행하세요 (Node.js 22.12 이상 필요).

```bash
npm install
node node_modules/electron/install.js   # 실행 엔진 내려받기 (이미 있으면 바로 끝남)
npm start
```

```bash
npm install                             # 의존성 설치
```

테스트용 예제 파일은 `samples/` 폴더에 있습니다(각 파일이 무엇을 확인하는지는 `samples/README.md`). 고쳐 쓰다가 원래대로 돌리려면 `node tests/e2e/make-samples.js`.

자동 테스트(`tests/e2e/`)는 테스트용 엑셀 파일을 실행할 때마다 임시 폴더에 만들고, 실제 앱 화면을 띄워 파일 인식·시각화 켜기/끄기·연결·고르기·끌어다 놓기·값 수정·실행 취소·합치기·나누기·저장 결과(= 미리보기)·저장 후 확인·컬럼이 많을 때·성능을 확인합니다. 시나리오 중 예외가 나거나 결과 요약 줄이 없으면 실패로 판정합니다.

### 서식 자동 기입 코드 구성

판단 규칙 모듈은 화면(DOM) 없이 node로 단위 테스트합니다. 화면 코드는 다른 탭처럼 격리된 preload 세계에서 동작합니다.

| 파일 | 하는 일 |
| --- | --- |
| `app-shell.js` | 화면 전환, 이 PC의 서식 보관함·설정 열기, 남은 임시 파일 정리 |
| `print-screen.js` · `forms-screen.js` · `settings-screen.js` | ① 서류 출력 · ② 서식 관리 · ③ 설정 화면 |
| `merge-fields.js` | 한글 메일머지 필드 사전(이름·주민번호·1~13·월1~일2·진료기간 …)과 입력 → 필드 값 규칙 |
| `form-library.js` | 서식 보관함: 파일 이름으로 분류, 필드·서류 목차 읽기, 저장·백업, 주소로 기관 추천 |
| `print-job.js` | 서식 채우기(메일머지 필드 / 자동 인식) → 한글 인쇄 → 임시 파일 지우기, 한글 파일로 저장 |
| `print-plan.js` | 서류 출력 규칙: 기관·구분에 맞는 서식, 필요한 입력과 빈칸, 출력 전 확인, 저장 파일 이름 |
| `settings.js` · `ui-dom.js` | PC 설정(담당자·부수·프린터) · 화면 요소 만들기 |
| `hancom.js` | Windows 한글 자동 조작(변환·PDF·인쇄) |
| `hwp-reader.js` | 구형 .hwp 읽기(표, 메일머지 필드, 서류 목차) |
| `hwpx-xml.js` · `form-model.js` | 한글 .hwpx를 원문 위치를 기억하는 표·칸·문단 모델로 읽기 |
| `form-recognize.js` · `field-dictionary.js` · `form-fill.js` | 기입 위치 인식({{필드}}·머리글 옆 빈 칸 …) → 입력 항목 연결 → 원문 XML의 그 자리만 바꿔 채우기 |

### 문서와 앱 보안

파일에서 읽은 이름·값은 HTML이 아닌 텍스트로 표시합니다. 앱 페이지는 Node 통합을 끄고 컨텍스트를 격리하며, 페이지 스크립트를 금지하는 CSP와 팝업·일반 페이지 이동 제한을 적용합니다. 파일 대화상자 등 IPC는 앱의 메인 프레임에서만 허용합니다.

기존 파일 처리와 백그라운드 검증 기능을 위해 앱 코드는 Node를 사용할 수 있는 **샌드박스 밖의 격리된 preload**에서 실행됩니다. 따라서 이는 전체 앱을 샌드박스화한 설계가 아니며, preload 코드와 공유 DOM의 안전한 처리가 여전히 중요합니다. Electron의 일부 특수 페이지 이동(예: `about:blank`)은 이동 차단 이벤트를 거치지 않을 수 있으나, 해당 페이지에서는 앱 preload를 초기화하지 않고 IPC도 허용하지 않습니다. 신뢰할 수 없는 문서는 계속 주의해서 다루세요.

## 지원 파일 형식

| 기능 | 지원 확장자 |
| --- | --- |
| 문서 양식 변환기 (원본/타겟) | `.xlsx`, `.xls`, `.xlsm`, `.csv`, `.hwpx`, `.hwpt`, `.hwp` (결과는 `.xlsx`) |
| 서식 자동 기입 (서식) | `.hwpx`, `.hwpt`, `.hwp` (`.hwp`는 설치된 한글로 `.hwpx`로 바꿔 보관) |

- CSV는 UTF-8(BOM 포함/미포함)·UTF-16(BOM)과 Windows 한글 기본 인코딩(CP949/EUC-KR)을 자동 판별하여 읽고, ①단계에서 직접 바꿀 수도 있습니다. 확장자와 실제 내용이 다르면(이름만 .xlsx인 CSV 등) 내용에 맞춰 읽고 알려줍니다.
- CSV·한글 문서 표처럼 값이 모두 글자로 들어오는 원본은, 탭1에서 열의 모든 값이 숫자 글자면 숫자로, 날짜 글자(`2026-01-05`, `2026/1/5`, `2026.01.05`, `2026년 1월 5일`, 뒤에 `13:05` 같은 시각 가능)면 날짜로 저장합니다. 하나라도 아닌 값이 섞인 열과 앞자리 0이 있는 코드(`00123`)는 글자 그대로 둡니다.
- 한글(`.hwpx`, `.hwp`) 문서는 **문서 안의 표**를 데이터로 읽습니다. 표가 여러 개면 "표 1", "표 2"...로 나뉘어 엑셀의 시트처럼 고를 수 있고, 결재란처럼 작은 표가 앞에 있어도 행이 가장 많은 표가 기본으로 선택됩니다. 병합된 셀은 왼쪽 위 칸에 값을 두되, 여러 행을 세로로 합친 셀("부서" 등)은 각 행에 같은 값을 채워 넣어 행마다 값이 빠지지 않게 합니다(2단 헤더도 이 덕분에 아래 헤더 행이 그대로 인식됩니다). 셀 안의 줄바꿈은 그대로 유지되고, 셀 속에 들어 있는 다른 표는 별도의 표로 분리됩니다.
- 구형 `.hwp`(한글 2002 이후의 HWP 5.0 바이너리 형식)도 같은 방식으로 표를 읽습니다. 추가 프로그램이나 한글 설치 없이 직접 해석하며, 표 캡션·글상자·각주는 표 데이터에 섞이지 않습니다. 다만 다음 문서는 읽을 수 없어 안내 메시지가 표시됩니다: 암호가 걸린 문서, 배포용으로 저장된 문서(내용이 암호화됨), 한글 97 이전(HWP 3.0) 문서.
