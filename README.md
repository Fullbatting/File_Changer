# 사회사업실 도우미

Electron + Node.js + JavaScript로 만든 데스크톱 프로그램입니다. 파이썬은 사용하지 않습니다.

> 이 브랜치(`mail-merge`)는 **사회사업실 도우미**(서식 자동 기입·메일머지) 프로그램입니다. 문서 양식 변환기는 `document-converter` 브랜치, 둘을 합친 통합 프로그램은 `main` 브랜치에 있습니다.

환자 인적사항을 한 번 넣고 제출 기관과 서류를 고르면, 등록해 둔 한글 서식에 내용을 채워 **한글로 바로 인쇄**합니다. 지금까지 엑셀(메일머지.xlsx)에 인적사항을 모아 두고 한글 메일머지로 서식마다 채우던 일을 대신합니다.

- **인적사항은 저장하지 않습니다.** 화면(메모리)에만 있고, 출력이 끝나면 지웁니다. 인쇄에 쓴 채운 임시 파일은 인쇄 직후 지우고, 프로그램이 갑자기 꺼져 남은 임시 파일은 다음 시작 때 지웁니다. 진행 기록에도 값은 남기지 않습니다.
- AI를 쓰지 않습니다. 모두 정해진 규칙으로 동작하고, 인적사항을 밖으로 보내지 않습니다.

### ① 서류 출력 (매일 쓰는 화면)

1. **인적사항**: 이름 · 주민등록번호 · 주소 · 연락처 · 작성일(비우면 오늘). 고른 서류에 진료기간·주질병·질병분류기호·진단일 칸이 있으면 그 칸만 더 나타납니다.
   - 생년월일(6자리), 주민등록번호 한 자리씩({{1}}~{{13}}), 작성일 월·일 두 자리씩({{월1}}{{월2}}·{{일1}}{{일2}}), 진료기간("26.01.02~")은 넣은 값에서 자동으로 만듭니다. 서식에 "2026년 {{월1}}…"처럼 연도가 미리 찍혀 있으면 작성 연도로 맞춥니다.
2. **제출 기관**: 주소의 시·군·구로 맞는 기관(양주시 → 양주시청, 서울 주소 → 서울형 포함)을 추천해 골라 둡니다. 직접 바꿀 수 있습니다.
3. **신청 구분**: 세대주 / 세대원.
4. **출력할 서류**: 그 기관의 서식이 지원 종류(긴급복지 국가형 · 경기도형 · 서울형 · 광주형 · 암환자 의료비)별로 나오고, 서식마다 들어 있는 서류 목차와 빈칸을 보여 줍니다.
5. **서식 출력**: 부수를 정해 기본 프린터(설정에서 바꿀 수 있음)로 인쇄합니다. 한글이 없는 PC에서는 [한글 파일로 저장]으로 채운 .hwpx를 저장할 수 있습니다(저장한 파일에는 인적사항이 들어 있으니 다 쓴 뒤 지워 주세요).

### ② 서식 관리

- 한글 서식(.hwp · .hwpx)이나 서식이 든 **폴더를 통째로** 끌어다 놓거나 [폴더째 추가]로 등록합니다. 파일·폴더 이름("양주시청-긴급복지지원 신청서(세대주).hwp", "★…", "보건소 암지원 신청서/…")으로 제출 기관 · 지원 종류 · 세대주/세대원 · 자주 쓰는 서식(★)을 알아보고, 확인 창에서 고친 뒤 등록합니다.
- 서식 안의 **한글 메일머지 필드**({{이름}} · {{주민등록번호}} · {{1}}~{{13}} · {{월1}} … {{담당자 번호}})를 한글 없이 직접 읽어 필드와 서류 목차([서식 1호] 현장확인서 …)를 보여 줍니다. 지금까지 쓰던 필드 이름 29개는 모두 사전에 있어 그대로 채워지고, 사전에 없는 필드는 [검토]에서 고정 글자 · 출력할 때 입력 · 비워 둠 중에서 정합니다.
- 메일머지 필드가 없는 서식은 서식 엔진의 자동 인식(머리글 옆 빈 칸, "라벨:  " 빈자리, 서명 줄, 날짜 틀 등)으로 채웁니다. [시험 저장]으로 가짜 예시 값을 채운 파일을 만들어 확인하세요.
- .hwp 서식은 설치된 한글로 .hwpx로 바꿔 보관합니다(등록할 때, 또는 처음 출력할 때). 원본 파일은 바뀌지 않습니다.
- 서식과 필드 연결은 이 PC에만 저장됩니다. [백업 내보내기]로 만든 .zip을 다른 PC에서 [백업 가져오기]하면 그대로 옮겨집니다.

### ③ 설정

담당자 · 직위 · 담당자 번호(암환자 의료비 서식의 {{담당자}} 등), 기본 부수, 프린터 이름, [한글 연결 확인].

### 한글 연결 점검 (Windows)

`tools\한글연결점검.bat`: 사용하실 PC에서 한글 자동 조작(변환·PDF·인쇄)이 되는지 확인합니다. 서식 파일(.hwp/.hwpx)을 bat 위로 끌어다 놓으면 그 서식을 .hwpx로 바꾸고, 메일머지 필드를 가짜 예시 값으로 채워 PDF로 만들어 `한글연결점검_결과` 폴더에 둡니다. `점검보고서.txt`에 한글 버전, 보안 모듈 등록 여부, 단계별 결과가 나옵니다.
- 한글이 자동 조작으로 파일을 열 때 "접근 허용" 창이 뜰 수 있습니다. 한컴의 보안 모듈(FilePathCheckerModule)을 등록하면 이 창 없이 진행됩니다.

## 설치 없이 바로 실행하기 (Windows)

1. 이 저장소 페이지에서 **Code → Download ZIP**으로 압축 파일을 내려받습니다.
2. 원하는 폴더에 압축을 풉니다.
3. 압축 푼 폴더 안의 **`run.bat`** 파일을 더블클릭합니다. 바탕 화면에 바로 가기를 만들어 두면 편합니다.
   - 검은 창(cmd)이 잠깐 열렸다가, 프로그램 화면이 제대로 뜬 것을 확인하면 저절로 닫힙니다. 프로그램은 그대로 계속 열려 있습니다.
   - PC에 없는 것은 `run.bat`이 알아서 내려받습니다(인터넷 연결 필요, 처음에 몇 분). 그다음부터는 준비를 건너뛰고 바로 엽니다.
     - **Node.js**: PC에 22.12 이상이 없으면 공식 Node.js(24.22.1, 약 40MB)를 프로그램 폴더 안 `runtime\node`에 내려받습니다. 내려받은 파일이 공식 검사값(SHA-256)과 같을 때만 씁니다. 관리자 권한이 필요 없고 PC 설정은 바꾸지 않습니다(지우려면 `runtime` 폴더를 지우면 됩니다).
     - **패키지와 프로그램 실행 엔진**(Electron, 약 100MB): 처음 실행할 때와 업데이트로 필요한 패키지가 바뀌었을 때 내려받습니다. 인터넷 연결이 없으면 이미 설치된 패키지 그대로 엽니다.
     - **한글(한컴오피스)**: 유료 프로그램이라 자동으로 설치할 수 없습니다. 처음 준비할 때 한글이 없으면 안내 창으로 알려 줍니다. 한글이 없어도 서식 등록과 인적사항 입력은 되지만, 출력과 한글 파일 저장에는 한글이 필요합니다.
   - 문제가 생기면(Node.js 내려받기 실패, 설치 실패, 프로그램이 열리자마자 닫힘, 화면이 제때 열리지 않음, 화면을 준비하지 못함, 화면이 갑자기 꺼짐, 예상하지 못한 오류) 오류 창으로 알려 줍니다.
   - 회사망처럼 외부 사이트가 제한된 곳에서는 최초 설치 때 `nodejs.org`(Node.js, PC에 없을 때만), `registry.npmjs.org`(패키지), `cdn.sheetjs.com`(.hwp 읽기 라이브러리), `github.com`과 GitHub 파일 서버(실행 엔진) 접속이 허용되어 있어야 합니다.

> **사전 준비**: 따로 설치할 것은 없습니다. PC에 [Node.js](https://nodejs.org/) 22.12 이상이 이미 있으면 그것을 쓰고, 없거나 버전이 낮으면 `run.bat`이 내려받습니다. 서류를 출력하려면 한글(한컴오피스)이 필요합니다.
>
> **지원 운영체제**: Windows 10/11 64비트, macOS 13 이상, 64비트 Linux. (실행 엔진 Electron 44가 32비트 Windows와 macOS 12 이하를 지원하지 않습니다.)

## 인터넷이 막힌 PC에서 실행하기

인터넷이 막힌 PC에서는 아무것도 내려받지 않고, 인터넷이 되는 PC에서 준비를 마친 폴더를 통째로 옮겨 씁니다. 프로그램은 외부로 아무것도 보내지 않으므로 인터넷은 처음 준비할 때만 필요합니다.

1. 인터넷이 되는 **64비트 Windows PC**에서 `run.bat`을 실행해 프로그램 화면이 뜰 때까지 기다립니다(준비 끝).
2. 프로그램 폴더 전체(`node_modules` 포함, 약 400MB)를 USB 등으로 인터넷이 막힌 PC에 복사합니다.
3. 막힌 PC에서 `run.bat`을 실행합니다.

- 막힌 PC에 Node.js가 없어도 됩니다. 준비된 폴더 안의 실행 엔진(Electron)에 Node.js가 들어 있어 그것으로 시작합니다.
- 업데이트한 뒤에는 인터넷이 되는 PC에서 다시 `run.bat`으로 준비한 폴더를 옮겨 오세요. 막힌 PC에서는 패키지 확인을 건너뛰고 설치된 그대로 엽니다.

## macOS / Linux에서 실행하기

`run.bat`은 Windows 전용입니다. macOS/Linux에서는 터미널에서 프로젝트 폴더로 이동한 뒤 아래 명령을 실행하세요 (Node.js 22.12 이상 필요).

```bash
npm install
node node_modules/electron/install.js   # 실행 엔진 내려받기 (이미 있으면 바로 끝남)
npm start
```

## 개발자용 명령어

```bash
npm install                             # 의존성 설치
node node_modules/electron/install.js   # Electron 실행 파일 내려받기 (Electron 42부터 npm install이 자동으로 받지 않음)
npm start                               # 앱 실행 (electron .)
npm test                                # 단위 테스트 + 화면 시나리오 + 보안 시나리오 (Linux 서버에서는 xvfb-run -a npm test)
npm run test:unit                       # 판단 로직 단위 테스트(Electron 없이): 메일머지 필드·서식 보관함·채우기/인쇄·서식 엔진·한글 자동 조작 스크립트
npm run test:screen                     # 화면 시나리오(서식 등록 → 출력 → 인적사항 지움). Linux 서버에서는 xvfb-run -a
npm run test:security                   # 보안 시나리오: 실제 main.js 창의 격리·CSP·IPC 발신자 확인. Linux 서버에서는 xvfb-run -a
```

## 앱 보안

- 앱 페이지는 Node 통합을 끄고 컨텍스트를 격리합니다(`src/main/app-security.js`). 페이지 스크립트를 금지하는 CSP를 두고, 팝업과 일반 페이지 이동을 막습니다. 파일 대화상자·사용자 데이터 폴더 같은 IPC는 앱의 메인 창·메인 프레임에서 온 요청만 받습니다.
- 앱 코드(`src/renderer/renderer.js` 이하)는 `src/main/preload.js`가 index.html에서만 불러오며, Node를 쓸 수 있는 **샌드박스 밖의 격리된 preload 세계**에서 실행됩니다. 전체 앱을 샌드박스화한 설계는 아니므로 화면에 글자를 넣을 때는 늘 텍스트로 넣습니다(`src/renderer/ui-dom.js`).
- Electron의 일부 특수 페이지 이동(예: `about:blank`)은 이동 차단을 거치지 않을 수 있으나, 그 페이지에서는 앱을 초기화하지 않고 IPC도 허용하지 않습니다.

- 프로그램 이름은 "사회사업실 도우미"이지만, 등록한 서식·설정을 저장하는 폴더는 예전 이름 그대로입니다(`%APPDATA%\doc-convert-mailmerge`). 이름을 바꿔도 등록해 둔 서식이 그대로 이어집니다.

## 코드 구성

화면 코드와 판단 규칙을 나눠 두었습니다. 판단 규칙(`src/autofill` · `src/engine`)은 화면(DOM) 없이 node로 단위 테스트합니다.

```
src/
  main/       Electron 메인 프로세스 — 앱 창·IPC, 보안 설정, preload
  renderer/   화면 — index.html · app.css, 서류 출력 · 서식 관리 · 설정 화면
  autofill/   서식 자동 기입 규칙 — 메일머지 필드 사전, 서식 보관함, 출력 규칙, 채우기·인쇄, 설정, 한글 자동 조작
  engine/     한글 서식 엔진 — .hwp/.hwpx 읽기, 문서 모델, 기입 위치 인식, 채우기
tests/
  unit/       단위 테스트 (npm run test:unit)
  screen/     화면 시나리오 (npm run test:screen)
  security/   보안 시나리오 (npm run test:security)
  fixtures/   테스트용 서식(가짜 예시)
tools/        한글 연결 점검 도구 (Windows)
```

| --- | --- |
| `main/main.js` · `main/app-security.js` · `main/preload.js` | 앱 창과 IPC, 보안 설정(격리·이동 차단·IPC 발신자 확인), 격리된 세계에서 앱 코드 불러오기 |
| `renderer/renderer.js` · `renderer/app-shell.js` | 화면 시작, 화면 전환, 이 PC의 서식 보관함·설정 열기, 남은 임시 파일 정리 |
| `renderer/print-screen.js` · `forms-screen.js` · `settings-screen.js` | ① 서류 출력 · ② 서식 관리 · ③ 설정 화면 |
| `renderer/common.js` · `renderer/ui-dom.js` | 진행 기록·오류 알림 · 화면 요소 만들기(글자는 늘 텍스트로) |
| `autofill/merge-fields.js` | 한글 메일머지 필드 사전(이름·주민번호·1~13·월1~일2·진료기간 …)과 입력 → 필드 값 규칙 |
| `autofill/form-library.js` | 서식 보관함: 파일 이름으로 분류, 필드·서류 목차 읽기, 저장·백업, 주소로 기관 추천 |
| `autofill/print-plan.js` | 서류 출력 규칙: 기관·구분에 맞는 서식, 필요한 입력과 빈칸, 출력 전 확인, 저장 파일 이름 |

| `autofill/settings.js` · `autofill/hancom.js` | PC 설정(담당자·부수·프린터) · Windows 한글 자동 조작(변환·PDF·인쇄) |
| `engine/hwp-reader.js` | 구형 .hwp 읽기(표, 메일머지 필드, 서류 목차) |
| `engine/hwpx-xml.js` · `engine/form-model.js` | 한글 .hwpx를 원문 위치를 기억하는 표·칸·문단 모델로 읽기 |
| `engine/form-recognize.js` · `field-dictionary.js` · `form-fill.js` | 기입 위치 인식({{필드}}·머리글 옆 빈 칸 …) → 입력 항목 연결 → 원문 XML의 그 자리만 바꿔 채우기 |

## 지원 서식 형식

- 한글 `.hwpx`(.hwpt)는 그대로 채웁니다. 구형 `.hwp`(HWP 5.0)는 한글 없이 필드·서류 목차를 읽고, 채울 때는 설치된 한글로 `.hwpx`로 바꿔 보관합니다.
- 읽을 수 없는 문서: 암호가 걸린 문서, 배포용으로 저장된 문서(내용이 암호화됨), 한글 97 이전(HWP 3.0) 문서.

## 주요 오픈소스 라이브러리

- [xlsx (SheetJS)](https://git.sheetjs.com/sheetjs/sheetjs) 0.20.3 — 구형 .hwp(OLE 복합 문서) 읽기에 쓰는 CFB 모듈 (Apache-2.0). npm 레지스트리의 xlsx는 0.18.5에서 업데이트가 멈춰 보안 수정이 없으므로, SheetJS 공식 배포처(`cdn.sheetjs.com`)에서 설치합니다.
- [pizzip](https://github.com/open-xml-templating/pizzip) — .hwpx(zip) 읽고 쓰기 (MIT)
- 화면 디자인: [Hallmark](https://github.com/Nutlope/hallmark)의 디자인 규칙과 Dose 테마(색·면·컨트롤 모양)를 따랐습니다 (MIT). 테마 글꼴 대신 한글 시스템 글꼴을 씁니다.
