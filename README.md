# 메일머지 자동기입

Electron + Node.js + JavaScript로 만든 데스크톱 프로그램입니다. 파이썬은 사용하지 않습니다.

> 이 브랜치(`mail-merge`)는 **메일머지 자동기입만** 들어 있는 단독 프로그램입니다. 문서 양식 변환기는 `document-converter` 브랜치, 두 기능을 함께 쓰는 통합 프로그램은 `main` 브랜치에 있습니다. 동의어 사전은 통합 프로그램과 같은 사용자 데이터 폴더를 쓰므로 그대로 이어 쓸 수 있습니다.

- **메일머지 자동기입**: Word(`.docx`) 또는 한글(`.hwpx`) 템플릿의 `{{변수명}}`을 자동 추출하여 값 입력 후 문서 생성. 두 가지 입력 방식을 지원합니다.
  - **직접 입력**: 변수마다 값을 한 번씩 입력해 문서 1건을 생성합니다.
  - **데이터 파일로 일괄 생성 (메일머지)**: 엑셀/CSV를 불러오면 각 행이 문서 한 개가 됩니다. 템플릿 변수와 데이터 컬럼은 동의어 사전 + 편집거리 기반 자동 매핑으로 연결됩니다(변수 순서와 상관없이 같은 이름을 먼저 연결). 데이터 파일의 헤더 행(위쪽 제목 줄·두 줄 머리글)도 자동으로 찾고, 건너뛴 행·머리글이 빈 열·글자 인코딩·확장자와 다른 내용·1904 날짜 체계를 로그로 알려줍니다. 매핑 테이블에서 바로 실제 데이터 값(앞 2행) 미리보기를 확인할 수 있습니다. 생성 전에 값이 비어 있는 변수를 검증하고 미리보기를 보여주며, 결과 파일은 지정한 컬럼 값으로 이름 지어 선택한 폴더에 한 번에 저장됩니다(동명이인 등 이름이 겹치면 "(2)", "(3)"을 붙여 구분). 한 행에서 오류가 나도 나머지 행 생성은 계속되며 끝에 결과를 요약합니다.
- **동의어 사전**: "성명"↔"이름"처럼 표기는 다르지만 같은 의미인 변수/컬럼명을 자동 매핑 2단계에서 즉시 연결해 주는 기능입니다. 작은 임베딩/언어 모델 없이, 사용자가 직접 관리하는 텍스트 사전만으로 동작해 설치 용량·실행 속도·예측 가능성(틀린 추측으로 개인정보가 엉뚱한 칸에 들어가는 일이 없음)을 그대로 유지합니다. 자주 쓰는 동의어는 기본으로 포함되어 있고, "📖 동의어 사전 관리" 버튼에서 한 줄에 한 그룹(쉼표로 구분)씩 직접 추가/수정할 수 있습니다.

## 서식 자동 기입으로 다시 만드는 중

메일머지를 **"환자 인적사항을 입력하고 부서를 고르면 등록해 둔 서식(한글 .hwpx/.hwp)에 자동으로 채워 바로 인쇄"**하는 프로그램으로 다시 설계하고 있습니다. 위의 기존 기능은 새 화면이 완성될 때까지 그대로 둡니다.

지금까지 만든 것:
- **서식 엔진**(`form-model.js`, `form-recognize.js`, `form-fill.js`, `field-dictionary.js`, `hwpx-xml.js`)
  - 기입 위치 자동 인식(규칙 기반, AI 없음): 표의 머리글 옆 빈 칸, 머리글 줄 아래 칸, 단위 앞("…명"), 칸 안 "라벨:  " 빈자리, 서명 줄, "년 월 일" 날짜 틀, `[   ]` 선택 표시(괄호 안 하위 선택·"있음"일 때만 쓰는 칸 포함), `{{변수}}`.
  - 같은 "성명"·"전화번호"도 표 왼쪽 묶음 머리글(등록 대상자 / 신청인 / 진단정보)로 누구 것인지 구분합니다.
  - 채우기: 원본 XML에서 바꿀 글자만 바꾸고, 빈칸 너비를 유지하며, 고른 보기는 `[ V ]`로 표시합니다. 서명란은 본인 신청이면 환자, 대리 신청이면 신청인 이름이 들어갑니다.
  - 실제 서식(암환자 의료비 등록 신청서)에서 기입 위치 44곳을 모두 찾는지 자동 테스트로 확인합니다.
- **한글 자동 조작**(`hancom.js`): Windows의 한글로 .hwp → .hwpx 변환, PDF 저장, 대화상자 없이 인쇄.
- **한글 연결 점검**(`tools\한글연결점검.bat`): 사용하실 PC에서 한글 자동 조작이 되는지 확인합니다. 서식 파일(.hwp/.hwpx)을 bat 파일 위로 끌어다 놓으면 그 서식을 .hwpx로 바꾸고, 기입 위치를 인식하고, 가짜 예시 값으로 채운 결과를 PDF로 만들어 `한글연결점검_결과` 폴더에 둡니다. 결과 폴더의 `점검보고서.txt`에 한글 버전, 보안 모듈 등록 여부, 단계별 성공 여부와 걸린 시간이 나옵니다.
  - 한글이 자동 조작으로 파일을 열 때 "접근 허용" 창이 뜰 수 있습니다. 한컴의 보안 모듈(FilePathCheckerModule)을 등록하면 이 창 없이 진행됩니다.

## 설치 없이 바로 실행하기 (Windows)

1. 이 저장소 페이지에서 **Code → Download ZIP**으로 압축 파일을 내려받습니다.
2. 원하는 폴더에 압축을 풉니다.
3. 압축 푼 폴더 안의 **`run.bat`** 파일을 더블클릭합니다.
   - 최초 실행 시 필요한 패키지와 프로그램 실행 엔진(Electron, 약 100MB)을 자동으로 내려받습니다 (인터넷 연결 필요, 몇 분 정도 소요).
   - 이후 실행부터는 이미 설치된 패키지를 빠르게 확인만 하고 바로 프로그램이 열립니다 (보통 몇 초 이내). 업데이트로 새 패키지나 새 실행 엔진 버전이 필요해진 경우에도 자동으로 함께 설치됩니다.
   - 인터넷 연결이 없는 상태에서 실행하면, 이미 설치되어 있던 패키지 그대로 프로그램을 계속 엽니다.
   - 회사망처럼 외부 사이트가 제한된 곳에서는 최초 설치 때 `registry.npmjs.org`(패키지), `cdn.sheetjs.com`(엑셀 읽기 라이브러리), `github.com`과 GitHub 파일 서버(실행 엔진) 접속이 허용되어 있어야 합니다.

> **사전 준비**: PC에 [Node.js](https://nodejs.org/) **22.12 이상** (LTS 버전 권장)이 설치되어 있어야 합니다. `run.bat` 실행 시 Node.js가 없거나 버전이 낮으면 안내 메시지가 표시됩니다.
>
> **지원 운영체제**: Windows 10/11 64비트, macOS 13 이상, 64비트 Linux. (실행 엔진 Electron 44가 32비트 Windows와 macOS 12 이하를 지원하지 않습니다.)

## macOS / Linux에서 실행하기

`run.bat`은 Windows 전용입니다. macOS/Linux에서는 터미널에서 프로젝트 폴더로 이동한 뒤 아래 명령을 실행하세요 (Node.js 22.12 이상 필요).

```bash
npm install
node node_modules/electron/install.js   # 실행 엔진 내려받기 (이미 있으면 바로 끝남)
npm start
```

## 개발자용 명령어

```bash
npm install                             # 의존성 설치
node node_modules/electron/install.js   # Electron 실행 파일 내려받기 (Electron 42부터 npm install이 자동으로 받지 않음)
npm start                               # 앱 실행 (electron .)
npm test                                # 단위 테스트 + 회귀 시나리오 (Linux 서버에서는 xvfb-run -a npm test)
npm run test:unit                       # 판단 로직 단위 테스트(Electron 없이): 데이터 파일 인식·변수 자동 매핑·서식 엔진·한글 자동 조작 스크립트
npm run test:legacy                     # 회귀 시나리오(직접 입력·일괄 생성, 한글 HWPX 표 데이터·템플릿, 전체 기능 점검 3단계). Linux 서버에서는 xvfb-run -a
```

## 지원 파일 형식

| 기능 | 지원 확장자 |
| --- | --- |
| 메일머지 템플릿 | `.docx`, `.dotx`, `.hwpx`, `.hwpt` |
| 메일머지 일괄 생성 데이터 | `.xlsx`, `.xls`, `.xlsm`, `.csv`, `.hwpx`, `.hwpt`, `.hwp` |

- CSV는 UTF-8(BOM 포함/미포함)·UTF-16(BOM)과 Windows 한글 기본 인코딩(CP949/EUC-KR)을 자동 판별하여 읽습니다. 확장자와 실제 내용이 다르면(이름만 .xlsx인 CSV 등) 내용에 맞춰 읽고 알려줍니다.
- 한글(`.hwpx`, `.hwp`) 문서는 **문서 안의 표**를 데이터로 읽습니다. 표가 여러 개면 "표 1", "표 2"...로 나뉘어 엑셀의 시트처럼 고를 수 있고, 결재란처럼 작은 표가 앞에 있어도 행이 가장 많은 표가 기본으로 선택됩니다. 병합된 셀은 왼쪽 위 칸에 값을 두되, 여러 행을 세로로 합친 셀("부서" 등)은 각 행에 같은 값을 채워 넣어 행마다 값이 빠지지 않게 합니다(2단 헤더도 이 덕분에 아래 헤더 행이 그대로 인식됩니다). 셀 안의 줄바꿈은 그대로 유지되고, 셀 속에 들어 있는 다른 표는 별도의 표로 분리됩니다.
- 구형 `.hwp`(한글 2002 이후의 HWP 5.0 바이너리 형식)도 같은 방식으로 표를 읽습니다. 추가 프로그램이나 한글 설치 없이 직접 해석하며, 표 캡션·글상자·각주는 표 데이터에 섞이지 않습니다. 다만 다음 문서는 읽을 수 없어 안내 메시지가 표시됩니다: 암호가 걸린 문서, 배포용으로 저장된 문서(내용이 암호화됨), 한글 97 이전(HWP 3.0) 문서.
- `.hwp`는 **메일머지 템플릿으로는 쓸 수 없습니다.** 결과 문서를 구형 바이너리 형식으로 다시 써야 하는데, 한글 프로그램에서 정상적으로 열리는지 확인할 수 없어 손상된 문서가 만들어질 위험이 있기 때문입니다. 한글 프로그램에서 "다른 이름으로 저장 > HWPX"로 저장한 뒤 그 파일을 템플릿으로 쓰세요.
